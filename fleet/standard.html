How we build our agents

The twelve points

An agent joins the crew only when these hold at the level of freedom it has.

  1. A gate outside the model

    Before any tool touches a target, code checks that you own it and have allowed it. No AI output can change that answer.

  2. Defined tools

    Every tool an agent can call has a fixed shape for what goes in and what comes out. A call that does not fit is refused, not repaired.

  3. Outside text is data

    Anything read from a site, a scanner or a mailbox is information and never an instruction. The agent cannot act on the outside world while it reads.

  4. Measured accuracy

    Every AI decision is tested against labelled examples. We measure how often it is right before the agent gets more freedom, and again after every change.

  5. Earned freedom

    Each agent has a declared level of freedom. It may only read, only propose, or act after a person approves. It moves up one step at a time after a measured test.

  6. Tight access

    Tools run with only the access the job needs. Each has a time limit and a short list of places it may reach.

  7. Budgets

    Every run has a cap on time, cost and AI use. The run stops when it reaches the cap.

  8. A log that cannot be quietly changed

    Every run and every AI decision is written down. Each entry is tied to the one before it, so a changed or missing entry shows.

  9. A person decides what matters

    Decisions that matter wait for a person. If nobody answers, nothing runs.

  10. Traces

    Every run keeps a record of each tool it called and each AI call it made, with time and cost. It links back to the log.

  11. A parts list

    Each agent has one record of the AI models, data, software packages and outside services it uses. The lists are generated from the code and a change is written to the log.

  12. Impact, incidents and retirement

    Before an agent gets more freedom we write down who could be harmed and how. Each agent has an owner for incidents. When an agent is retired its keys are revoked and its data is deleted.

Standards we follow

The crew is built to these and maps to them. None of them is a certification.

NIST CSF 2.0
The six functions every skill is mapped to, from Govern to Recover.
AIUC-1
A security, safety and accountability standard for AI agents.
ISO/IEC 42001
A management system for the responsible use of AI.
ISO/IEC 42005
How to assess the impact of an AI system on people.
NIST AI RMF and its generative AI profile
US guidance on mapping, measuring and managing AI risk.
OWASP Top 10 for LLM and agentic applications
The most common ways AI apps and agents are attacked or misused.
EU AI Act
European law on how AI systems are built and used. It covers logging, human oversight and telling people when AI is involved.
ISO/IEC 27001
The standard clients ask for to show that information security is managed.
CIS Controls v8.1
A practical list of safeguards sized for small organisations.
SLSA and Sigstore
How software is built and signed so it can be traced to its source.
MITRE ATLAS
A catalogue of attacks on AI systems. It guides how we test AI features.
Singapore IMDA framework for agentic AI
Singapore's guidance on governing AI agents.
Hong Kong Cap. 653
Hong Kong law on the security of critical infrastructure computer systems.
EU Cyber Resilience Act
European law on the security of digital products. It covers reporting exploited flaws and listing software parts.
