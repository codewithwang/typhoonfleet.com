How it works.

One run each morning, Hong Kong time. Each source is read on its own, so one dead feed does not stop the rest.

Gather

Reads the CVE.org record list (the master list of published flaws), the CISA Known Exploited Vulnerabilities catalogue, the FIRST EPSS exploit-probability scores, and CISA's industrial control system advisories.

Rebuild

The US National Vulnerability Database no longer fills in severity and affected products for most new entries. Glass takes those details from the publisher's own record instead, and stamps each field with its source.

Score

Confirmed exploitation counts most. Then the probability of exploitation in the next 30 days, whether the vendor is on a watch list, whether industrial systems are affected, and how recent it is.

Publish

Writes the ranked list and a short digest: new exploited entries since the last run, and the count for the week. Each run leaves one line in the fleet's decision log.

What it does, and what it does not.

It does

  • Read four public sources every day and keep a record of each run.
  • Rebuild missing severity, weakness type and affected products from the publisher's record.
  • Show, field by field, where each detail came from.
  • Rank by confirmed and likely exploitation, not by severity alone.

It does not

  • Know what you run. Nothing on the list is matched to your domain or your code.
  • Send you alerts. You read the list; it does not come to you.
  • Run in real time. A flaw published at noon is read the next morning.
  • Score for your industry. The watch lists are tuned to Asia-Pacific financial services and industrial vendors, and are kept by hand, so a vendor name it does not recognise is a flaw it can miss.
  • Read GitHub advisories, OSV, the EU database or VulnCheck. Those four sources are planned, not connected.
