One request, one agent, one written reason.

Bridge is the dispatcher. It reads a request, picks the one agent whose job it is, checks the rules for that job, and writes the decision down. It never runs a check itself. Today it is run by the operator, not by you.

What Bridge carries.

Three pieces of kit. Two work today.

How a request is routed.

Four steps. A request that fails a step stops there, and the refusal is logged like anything else.

Match

Every job in the fleet has a short description file: what it does, what it needs, and the words that call for it. Bridge matches the request against those. A small AI model is asked only when the match is unclear.

Check the level

Each job carries a level. Jobs that only read and report are sent straight away. Jobs that recommend an active step need a person to say yes at the keyboard. Anything above that is refused.

Check permission

A job that touches something you own needs a signed permission naming exactly that target, with an expiry date. No file, an expired file, or an unconfirmed owner means no run. The agent checks every target again itself.

Send and record

The job runs under its own agent. Bridge writes one line to the log with the outcome.

What is docked today.

Four jobs across three agents. Adding a fifth means writing its description file. Nothing in Bridge changes.

What it does, and what version 0 leaves out.

It does

  • Route a request to one job, with a confidence figure.
  • Refuse a job above its allowed level, or without valid permission, and log the refusal.
  • Keep one line per decision.
  • Take a new job without a code change.

It does not, yet

  • Take requests from you. There is no chat or web surface; the operator runs it from a command line.
  • Sit in the path of the nightly runs. Scheduled jobs start on their own timers and record their own lines. Bridge's routing was proved by hand in September 2026.
  • Send findings to named owners. With one operator there is one owner.
  • Write the monthly brief.
  • Protect the log from tampering. Chaining each line to the one before is planned.
  • Review itself. A daily audit of the logs for off-scope or failed runs is planned.
