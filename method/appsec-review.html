How Squall reviews an application.

The full review checks the code and the thing actually deployed, in one run. This page is the method. Results are never published.

The question it answers.

Is this code, and its deployment, safe to ship. A review that stops at the repository misses the hosting headers, the hosts the shipped app can talk to, what the app leaves in the browser, and the accounts that can publish a new build. This review covers both halves and writes down what it could not cover.

Eleven steps, least invasive first.

Every step saves its raw output beside the report, so each finding can point at the line, header, host or field that proves it.

Permission

A signed permission file names the repository, every hostname, and the kinds of action allowed. One target outside it and the run stops before any tool starts.

Secrets in history

Two scanners read the full history of the code, not just the current files. Values are hidden before they reach the evidence. A credential proved to be live is rated High on its own.

Dependency flaws

Every flawed package, with its identifiers and the version that fixes it. Whether the flaw can be reached from the running app is decided at step 11, not by the scanner.

Static analysis

Rule sets for the language and framework, over the application's own source. A run that scans no files is a failure, never "no findings".

Unsafe patterns

A search of the source for patterns that turn user input into code: raw HTML insertion, eval, open cross-origin rules, switched-off certificate checks, shell calls, private keys.

Response headers

The content security policy and what it allows, HSTS, framing, content sniffing, referrer and permissions policies, caching of the page, version leaks.

Hosts in the shipped app

Every hostname inside the served JavaScript, minus an expected list where each entry has a reason. Anything left is a host the app could talk to that nobody explained.

Browser traffic and storage

A headless browser runs the app's real flow at human pace and records every host contacted, every policy violation, and what was left in storage and cookies.

Policy test on a preview

When a header change is proposed, the same flow runs against a preview first, so a policy that breaks the app is caught before it goes live.

Hostile input and account settings

Crafted inputs go through the app's own parsing, offline: lookalike domains, oversized subjects, malformed dates. Alongside, read-only checks on the accounts that can publish.

Judgement

A person reads every unproven item and decides: reachable, or cleared with a reason. Anything that needed a live human session is listed as not covered, by name.

The rules it runs under.

Permission before contactNo target is touched without a signed file naming it. An exclusion list wins over everything: a third party's systems are seen as traffic, never probed.
Read-onlySquall reports and recommends. It changes nothing in the repository, the deployment or any account. Fixes are a separate act.
Human paceOne request per address, one browser flow. No fuzzing of a live host.
Every run recordedOne line in the decision log per run: what was asked, under which permission, the outcome, and where the report is. Reports stay on the operator's machine.

What comes out.

One report in a fixed shape: the permission, the tools and versions, a ranked table, then for each finding the evidence, why it matters and the fix. It ends with everything that passed and everything that was not covered.

CriticalDirect compromise, data theft or code execution, confirmed and reachable.
HighSerious exposure, exploitable with modest effort, or a confirmed sensitive leak.
MediumA real weakness that needs conditions to exploit, or a missing layer of defence.
LowA minor hardening gap with limited impact.
InfoAn observation with no direct risk.
UnverifiedPlausible but not proven. The missing proof is named. It is never presented as confirmed.

On a schedule, a new report is written only when the ranked findings change. The log line is written every time.

The tools.

Open source, run on the operator's machine. Nothing uploads your code or your targets to a service.

Secrets in historytrufflehog, gitleaks
Dependency flawsosv-scanner
Static analysissemgrep
Headers and shipped appA plain HTTP client
Traffic, storage, policy testPlaywright with headless Chromium
Live-session traffic proofmitmproxy
Account settingsThe providers' own read-only interfaces

No AI model runs the checks. A small model may route a request; a large one is used only to help with the judgement at step 11.
